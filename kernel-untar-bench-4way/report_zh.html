3月成本估算 500 GB / 月 · us-east-2

费率取自 AWS Pricing API 官方 us-east-2 价格（2026 年 9 月）。假设：每月存储并写入 500 GB、读取 500 GB（1 次全量读）；S3 Files 高性能层活跃集 = 全部 500 GB；JuiceFS 默认 4 MiB 块 → 500 GB ≈ 128,000 个对象（写 128k PUT + 读 128k GET）；JuiceFS 的 Redis 独占一台 c7i.4xlarge 全天候（720 小时）运行 + 30 GB gp3 系统盘。

关键：JuiceFS 的隐性成本陷阱。只看"存储 + IO"，JuiceFS 便宜到离谱（约 $12/月，只付 S3 Standard），EFS（$195）也略优于 S3 Files（$207）。但 独占的 Redis EC2 是 JuiceFS 的隐性 TCO 大头——一台 c7i.4xlarge 全天候运行每月 ~$514，直接把 JuiceFS 顶到 $529/月，成为三者中最贵，约为全托管 EFS 的 2.7 倍。托管的 EFS / S3 Files 没有这个"计算底座"成本，所以在 500 GB 这种中小规模决定性胜出。JuiceFS 只有在多 TB / PB 级、固定元数据节点成本被摊薄后才有经济性——而且那时你会合理调优（或共用）元数据节点，而不是独占一台 c7i.4xlarge。500 GB 规模，EFS 是最划算的理性选择；JuiceFS 只有在无视其必需的元数据服务器时才"最便宜"。

✓总体要点

  • 本地 EBS 秒级完成 ~10 万文件的解压/克隆；所有网络存储都慢 2 个数量级以上——瓶颈是逐文件元数据网络往返延迟，不是带宽（单线程把每个小文件的 create 串行化了）。
  • 性能：EFS ≈ S3 Files（两项测试都咬得很紧）；JuiceFS 明显落后（解压 1.5×、clone 1.9×），FUSE + Redis 往返 + S3 分块写在海量小文件场景吃亏。
  • 成本：500 GB 规模下 EFS（$195）最省，S3 Files（$207）接近；JuiceFS 因独占 Redis EC2 反而最贵（$529）。
  • 选型：中小规模（≤ 数 TB、小文件密集）优先托管的 EFS；JuiceFS 的经济性只在多 TB/PB 级、元数据节点成本被摊薄时才体现。
